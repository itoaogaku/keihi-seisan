# 経費精算PDF作成アプリ

個人のクレジットカード明細から、会社ごとの経費精算PDFを作成し、
Googleスプレッドシートに保存できるWebアプリです。

## 1. システム構成

サーバー側にDBを持たず、各ユーザーのGoogleスプレッドシート宛にブラウザから
直接データを送る構成にすることで、共通の1つのURLを同僚と共有しても
データが混ざらないマルチテナント構成を実現しています。

```
                共通のURL (Vercel)
                        │
        ┌───────────────┴───────────────┐
        │        Next.js アプリ           │
        │  (フロントエンドのみ・DBなし)     │
        └───────────────┬───────────────┘
                         │ ブラウザのlocalStorageに
                         │ 「自分のGAS URL」を保存
        ┌────────────────┼────────────────┐
        │                │                │
   自分のブラウザ      同僚Aのブラウザ    同僚Bのブラウザ
        │                │                │
        ▼                ▼                ▼
  自分のGAS URL      同僚AのGAS URL   同僚BのGAS URL
        │                │                │
        ▼                ▼                ▼
  自分のスプレッドシート 同僚Aのシート    同僚Bのシート
```

- **フロントエンド(Next.js, Vercelにデプロイ)**: CSV取り込み・仕分け・集計・PDF出力を担当。
- **設定(接続設定)**: 各ユーザーが自分のGAS WebアプリURLをブラウザのlocalStorageに保存。
- **バックエンド(GAS)**: 確定した経費データをPOSTで受け取り自分のスプレッドシートに追記する処理と、
  保存済みデータをGETで一覧取得する処理(`?action=list`)を持つ薄い層。
- **データベース**: 各ユーザー自身のGoogleスプレッドシート(サーバー側は一切保持しない)。

## 2. 画面設計(ワイヤーフレーム)

トップ画面は「保存済みデータの一覧(履歴)」です。新しい明細の入力・編集は
別画面(`/new`)で行い、保存すると一覧の一番上に追加されて戻ってきます。

すべての画面の最上部には共通のヘッダー(タブナビゲーション)が常に表示され、
「経費精算」「出張報告書」「設定」をタブとしてクリックして切り替えられます。
現在表示中のタブは下線でハイライトされます。PDF印刷時にはヘッダーは表示されません。

一覧の各行は、GASに保存した1回分の操作(下書き保存 or 確定)ごとに1件表示されます
(保存日時が同じ明細をまとめています)。行をクリックすると展開し、含まれる明細を確認できます。
新しい発行日で保存すると一番上に追加されるので、常に最新のものが上に来ます。
「新規作成」ボタンから明細の取り込み・仕分け・保存画面(`/new`)を開けます。

各行の「編集」ボタンを押すと、その明細を`/new`に読み込んで編集できます。
編集後に「下書き保存」または「経費精算PDFを出力」を押すと、元の行は削除され、
新しい内容で置き換わります(重複して増えることはありません)。

各行の「削除」ボタンを押すと、確認ダイアログの後、その保存操作に含まれる明細一式が
スプレッドシートから完全に削除されます(取り消せません)。

締め日・集計期間による絞り込みはありません。取り込んだ明細はすべて常に集計対象になります。

「プレビューしてPDFを出力」を押すと、まだ保存・PDF作成は行わずに、実際に出力される
PDFと同じ内容のプレビュー画面が表示されます。プレビュー画面で「編集に戻る」から明細の
修正に戻れるほか、内容に問題がなければ「この内容でPDFを出力」を押すことで確定操作
(スプレッドシートへの保存とPDF作成をまとめて行う)を実行し、成功すると一覧画面(`/`)に
戻ります(保存に失敗した場合はPDFも作成されません)。
まだ確定しない下書き段階のデータは(プレビューを経由せず)「下書き保存」で残しておけます
(同じく保存後は一覧画面に戻り、一番上に追加されます)。

仕分け(請求先)のプルダウンは、選択した組織ごとに背景色が変わるようにして視認性を高めています
(青山学院大学陸上競技部は緑)。未選択(未仕分け)の行は赤枠で強調されます。

請求先には、実在の組織以外に「除外(プライベート決済)」と「精算済み(請求対象外)」の
2種類の特殊な選択肢があります。どちらも集計・PDF・出張報告書への転記の対象外になる点は
同じですが、意味合いが異なります。「除外」はプライベートな決済(会社に請求しないもの)、
「精算済み」はすでに別の方法(他の経費精算など)で清算済みのため、このアプリでは
二重に請求したくない明細に使います。

メモ欄は、請求先を「除外」にすると自動的に「-」表示になり編集できなくなります
(プライベート決済にはメモが不要なため)。「精算済み」ではメモは引き続き入力できるため、
どこで精算済みかを書き残しておくのに使えます。それ以外の請求先を選んだときは、
過去に確定・下書き保存した明細の中に同じ「内容」のものがあれば、そのメモを自動的に引き継ぎます。

仕分け(請求先組織)自体も、CSV取り込みや決済の手入力の時点で未仕分けであれば、
過去に同じ「内容」の明細を仕分けた実績があれば自動的に同じ請求先(除外・精算済みを含む)を
セットします。ユーザーが手動で選び直した仕分けは上書きしません。

「決済の追加(手入力)」では、CSV明細に含まれない支払いを1件ずつ追加できます。支払日・内容・
金額に加えて「方法」のプルダウンでカード/現金を選べます(以前は現金専用の入力欄でしたが、
クレジットカードでもCSVに含まれない支払い(例: 締め後の追加払い)を手入力できるよう拡張しました)。
なお、CSVのテキスト貼り付けによる取り込み機能は廃止し、CSVファイルの取り込みに一本化しました。

同じ「カード」払いでも、CSVから取り込んだものと手入力で追加したものは、方法欄のバッジで
見分けられます。CSV取り込み分は灰色の「カード」、手入力分は青色の「カード(手入力)」と
表示され、一覧画面で保存済みデータを確認するときも同じ区別が保たれます(現金払いは
CSVには含まれないため区別する必要がなく、常に「現金」と表示されます)。

「現金」「カード(手入力)」の明細(=手入力で追加したもの)には、行の一番右に鉛筆アイコンの
「編集」ボタンが表示され、支払日・方法・内容・金額を後から修正できます(打ち間違いの
訂正用)。CSVから取り込んだ明細は、明細書の内容をそのまま反映したものなのでこのボタンは
表示されず、内容を直接編集することはできません(修正したい場合は削除して再度取り込むか、
手入力で追加し直してください)。

「明細の仕分け」の一覧では「日付順に並び替え」ボタンで、現在表示中の明細を利用日の昇順に
並べ替えられます。CSV取り込み・手入力・出張報告書からの転記などで順序がバラバラになった
明細を整理するのに使います。

CSVの一括取り込みは同じ期間の明細を何度も含んでしまいがちなので、取り込んだ明細の「利用日」と
「内容」が、スプレッドシートに保存済み(確定/発行済み)の明細と一致する場合は「精算済み?」の
黄色いバッジが表示され、行全体も薄い黄色でハイライトされます。すでに精算した明細を誤って
二重に請求してしまわないよう、取り込み直後にこのバッジがついた行を確認してください
(下書き保存のみの明細とは一致しても警告しません)。

CSVファイルから取り込むと、「1. 明細の取り込み」の見出し右側に
「(ファイル名) 読み込み済み」と表示されます(複数のクレジットカードのCSVを
まとめて取り込んだときは、ファイルごとにバッジが並びます)。決済の手入力で
追加した明細にはファイル名が付きません。取り込み元ファイル名は
スプレッドシートにも保存されるため、一覧画面で該当のエントリを展開したときや、
「編集」で開き直したとき(見出し右側のバッジとして)にも確認できます。

各行のチェックボックスで明細を選び「選択した◯件を出張報告書へ転記」を押すと、
出張報告書画面(下記)の出張経費欄にその内容(日付・内容・金額・メモ→備考)が
そのまま追加されます(「除外」「精算済み」に仕分けた明細は転記対象外)。

「2. 集計結果」の組織別の内訳は、それぞれ1行(1カード)で横幅いっぱいに表示され、
組織名が折り返されないようにしています。並び順は「仕分け(請求先)」のプルダウンと
同じ順番(組織A→組織B→組織C→組織D)です。

「印刷してPDFに保存」を押します。これによりブラウザ標準の印刷画面が開くので、
印刷先(送信先)で「PDFに保存」を選ぶとPDFファイルとして保存できます

内容の変更は入力のたびにこのブラウザへ即座に自動保存されるほか、GAS WebアプリURLを
設定していれば、少し間を置いて(1.5秒ほど)スプレッドシートへも自動的に同期されます
(毎回の入力ごとに通信しないよう、まとめて送るようにしています)。ブラウザのデータが
消えてしまった場合や別のブラウザで開いた場合でも、スプレッドシート側にデータが
残っていれば自動的に復元されます
(html2canvasでの画像化ではなくブラウザの印刷機能を使うため、文字が鮮明でコピーもできます)。

### スマートフォン(iPhoneなど)での表示

各画面のヘッダーやカードの見出しは、画面幅が狭いときはタイトルとボタン群を
縦に積み重ねる形に切り替わり、ボタンが画面外にはみ出したりタイトルの漢字が
1文字ずつ縦に折り返されたりしないようにしています。一覧の明細テーブルなど
列数が多い表は、日付・請求先組織などの列を折り返さずに保ったまま、必要な
場合は横スクロールで残りの列(内容・メモ・金額など)を確認できます。

iPhoneのSafariで「共有」→「ホーム画面に追加」を行うと、領収書をモチーフにした
紫色のアイコン(`app/apple-icon.tsx`で自動生成)がホーム画面に追加され、ホーム画面
からタップするとステータスバーだけのアプリ風表示(Safariのアドレスバーなし)で
起動します。ホーム画面上の表示名は「経費精算」になります。

## 3. 使い方

1. トップ画面(`/`)は保存済みデータの一覧。「新規作成」から`/new`を開く。
2. カード会社サイトからダウンロードしたCSVファイルを取り込む。CSVに含まれない決済は
   「決済の追加(手入力)」からカード/現金を選んで1件ずつ追記する。
3. 各明細の「仕分け」列で請求先組織(または「除外」「精算済み」)を選択する(プルダウンは組織ごとに色分けされる)。必要に応じてメモも入力する。
4. 集計結果を確認し、発行日を指定する(デフォルトは当日)。
   - 途中経過を残したいだけなら「下書き保存」を使う(PDFは作らない)。
   - 内容が確定したら「プレビューしてPDFを出力」を押し、プレビュー画面で
     「この内容でPDFを出力」を押す。これは確定操作として、
     スプレッドシートへの保存とPDF作成をまとめて行う
     (初回は「設定」画面でのGAS URL登録が必要。手順は [`gas/README.md`](./gas/README.md) を参照)。
   - どちらも保存に成功すると一覧画面(`/`)に戻り、保存した内容が一番上に表示される。
5. トップ画面の一覧では、行をクリックすると保存済みの明細を確認できる。「編集」ボタンで
   その内容を`/new`に読み込んで修正し、再保存すると元の行と置き換わる。
   発行日で絞り込んだり、一覧の内容をそのままCSVファイルとして書き出せる。
6. 出張に伴う経費がある場合、`/new`の明細表でチェックを入れて「選択した明細を出張報告書へ転記」
   を押すと、出張報告書が新規作成されて経費として転記される。出張報告書は`/business-trip-report`
   の一覧で管理し、「新規作成」で作ってから日時・場所・目的・報告内容を入力する。
   出張経費欄では期間を指定して過去の保存済み明細を検索し、ポップアップから選んで追加することもできる。
   「プレビューしてPDFに出力」で見た目を確認したうえで、ブラウザの印刷機能からPDFとして保存できる。

CSVの列名はカード会社ごとに異なりますが、`利用日`/`ご利用日`/`日付`、
`利用店名`/`摘要`/`内容`、`利用金額`/`金額` などの一般的な表記を自動認識します。
認識できるヘッダーが見つからない場合は「先頭列から日付・内容・金額」とみなして読み込みます。

## 4. 技術構成

| 領域 | 技術 |
| --- | --- |
| フロントエンド | Next.js 14 (App Router) + TypeScript + Tailwind CSS |
| UIコンポーネント | shadcn/ui スタイルの自前実装コンポーネント |
| CSV解析 | PapaParse |
| PDF出力(経費精算書) | jsPDF + html2canvas(ブラウザ描画をそのまま画像化するため、日本語フォント埋め込みが不要) |
| PDF出力(出張報告書) | ブラウザの印刷機能(プレビュー画面→印刷→PDFに保存) |
| バックエンド | Google Apps Script(Webアプリとしてデプロイ、ユーザーごとに個別) |
| データベース | 各ユーザー自身のGoogleスプレッドシート |
| ホスティング | Vercel |

## 5. セットアップ・開発

```bash
npm install
npm run dev       # http://localhost:3000
npm run build     # 本番ビルド確認
```

### Vercelへのデプロイ

このリポジトリをVercelにインポートしてデプロイするだけで動作します。
サーバー側の環境変数やDB設定は不要です(GAS URLは各ユーザーのブラウザに保存されるため)。

### 同僚が使い始めるとき

1. VercelのURLにアクセスする。
2. [`gas/README.md`](./gas/README.md) の手順で、自分のスプレッドシート宛にGASをデプロイする。
3. アプリの「設定」画面で発行されたGAS URLを登録する。

これにより、共通のURLを使いながらも、各自のデータは各自のスプレッドシートにのみ保存されます。
